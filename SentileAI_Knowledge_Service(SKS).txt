SentinelAI Engineering Intelligence Service - Development Prompt
You are a Principal Software Architect and Senior Backend Engineer.

Your task is to design and implement a new Spring Boot microservice called

Engineering Intelligence Service (EIS)

This service is a completely independent microservice inside SentinelAI.

DO NOT modify existing RCA services.

The objective is NOT to perform Root Cause Analysis.

The objective is to continuously build Engineering Intelligence by synchronizing engineering metadata from multiple enterprise systems.

This service will later be consumed by the existing RCA pipeline.

I would make one architectural change

Instead of naming it Engineering Intelligence Service, I would name it:

SentinelAI Knowledge Service (SKS)

or

Engineering Knowledge Service (EKS)

Why?

Because in the future, your architecture naturally becomes:

                     SentinelAI Platform

                    API Gateway
                         │
────────────────────────────────────────────────────────────

RCA Service

Knowledge Service

AI Gateway Service

Memory Service

Agent Service

Observability Service

Notification Service

Authentication Service

UI

Then the flow becomes:

Elastic Alert
      │
      ▼
RCA Service
      │
      ▼
Engineering Knowledge Service
      │
      ├── Git
      ├── Jira
      ├── Confluence
      └── Jenkins
      ▼
Context Bundle
      ▼
AI Gateway
      ▼
Evidence-Based RCA

This separation of responsibilities is cleaner:

Knowledge Service owns engineering context.
RCA Service owns incident diagnosis.
AI Gateway owns model interactions.
